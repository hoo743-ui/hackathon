## [수정] 슬라이드 12 — 개발 중 해결한 문제 (표에 행 추가)
| 문제 | 원인 | 해결 |
|---|---|---|
| 학교 Wi-Fi에서 카메라 컴퓨터 → 서버 요청 0건 | 같은 Wi-Fi 안의 기기 간 통신 차단 | 휴대폰 핫스팟 + 서버 위치 신호로 IP 자동 추적 |
| 카메라 프로그램이 서버에 흔적을 남기지 않음 | 모델 확인 단계에서 멈춘 뒤에야 서버 접속 시작 | 시작 즉시 서버 접속(상태 보고) → 문제 위치 바로 표시 |
| 센서 없는 3칸 때문에 "장치 저하" 표시 | 측정 기록이 없는 칸도 고장으로 계산 | 센서 미설치 칸은 '수신 없음'으로 구분 |
| 원격 제어 버튼을 누르면 시간 초과 오류 | 서버에서 Arduino로 가는 경로가 없는 구성 | 원격 제어 비활성 + 안내 문구 |
| 화면이 개발 도구처럼 보임 | 고정폭 글꼴·큰 글씨 | Pretendard + 상용 앱 크기 + 브랜드 색 체계 |

## [추가] 슬라이드 11-1 (슬라이드 11 뒤) — 운영 편의
- **제목**: 현장 설정은 0분
- **핵심 문장**: 카메라 컴퓨터는 받아서 실행만 한다
- **본문**
  - 팀 공통 설정(신뢰도 0.65, 중복 방지 시간, 자동 추적 등)은 저장소의 `settings.env`로 배포 → `git pull` 하면 자동 적용
  - 비밀값(서버 토큰)과 기기별 값(COM 포트·카메라 번호)은 카메라 컴퓨터에만 보관 — 공개 저장소에 올리지 않음
  - `START_SMART_RECYCLE.bat` 더블클릭: 최신 코드 받기 → 라이브러리 확인 → 실행
  - 프로그램 안 설정 화면: 서버 주소 · COM 포트 자동/수동 · 카메라 탐색 · 모델 파일 선택
- **시각 자료**: 3단 흐름 (git pull → 설치 확인 → 실행) + 설정 창 캡처
- **발표 멘트**: "현장에서 설정을 만지다 시간을 쓰지 않도록, 설정도 코드처럼 배포합니다."
