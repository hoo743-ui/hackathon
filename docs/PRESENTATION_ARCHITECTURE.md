# 발표용 아키텍처 요약 (PPT 원고)

> 슬라이드 1장 = 섹션 1개. 각 섹션의 굵은 문장이 슬라이드 제목, 글머리표가 본문이다.

---

## 1. SMART RECYCLE — 공공장소 스마트 분리수거
- 시민이 쓰레기를 넣으면 **AI가 종류를 인식**하고 **서보모터가 해당 칸으로 분류**
- 4칸(플라스틱·캔·종이·일반)의 적재율을 초음파 센서로 실시간 측정
- 관리자: **웹**(운영 현황·기록) + **모바일 앱**(현장 확인·알림·제어)이 같은 데이터를 실시간 공유
- 전부 무료 오픈소스, 인터넷 없이 로컬 네트워크만으로 동작

## 2. 전체 구조 한 장 요약
```
 투입 → [AI 노트북: 카메라 → YOLO 분류] ──HTTP──┐
                                                 ▼
[ESP32 + 초음파 4 + 서보 4] ⇄ MQTT(Mosquitto) ⇄ FastAPI ⇄ PostgreSQL
        (또는 가상 장치)                           │
                                     REST + WebSocket
                                   ┌──────┴──────┐
                              관리자 웹 (5메뉴)  관리자 앱 (4탭)
```
- 처리 흐름: 투입 → 촬영 → AI 분류 → 서버 판단(자동 모드·신뢰도) → 서보 작동 → 장치 응답(ACK) → 적재율 갱신 → 웹·앱 실시간 반영
- 하드웨어 ↔ 서버: **MQTT** (가볍고 끊김에 강한 IoT 표준)
- 서버 ↔ 화면: **REST**(초기 로딩) + **WebSocket**(실시간 변경)

## 3. 기술 스택
| 계층 | 기술 | 선택 이유 |
|---|---|---|
| 하드웨어 | ESP32, HC-SR04 ×4, SG90 ×4 | Wi-Fi 내장, 저가 |
| 펌웨어 | PlatformIO, Arduino, PubSubClient | 재현 가능한 빌드 |
| 브로커 | Eclipse Mosquitto | 경량, 인증·ACL·LWT 지원 |
| 백엔드 | FastAPI, SQLAlchemy, Alembic | 비동기, 타입 검증(Pydantic) |
| DB | PostgreSQL 16 | 현재 상태 + 이력 분리 저장 |
| 웹 | React, TypeScript, Vite, Recharts | 실시간 대시보드 |
| 앱 | React Native, Expo | iOS/Android 동시 지원 |
| 인프라 | Docker Compose (Colima) | 명령 한 줄로 실행 |

## 4. 데이터 흐름 ① — 센서 → 화면
1. ESP32가 센서 4개를 **순차 측정**(간섭 방지), 5회 측정 **중앙값** 사용
2. 원시 거리값만 MQTT로 전송
3. 서버가 쓰레기통별 보정값으로 **적재율 계산** (계산은 서버 한 곳에서만)
4. DB 저장(현재 상태 + 이력) → WebSocket으로 웹·앱에 동시 전파
- 센서 오류 시 마지막 정상값 유지 → "오류"와 "0%"를 구분

## 5. 데이터 흐름 ② — 앱 → 모터
1. 앱에서 "플라스틱 배출구" 버튼 → 서버 API (토큰 인증)
2. 서버 검증: 장치 연결·진행 중 명령·자동/수동 모드·긴급정지 상태
3. MQTT로 명령 전송 → ESP32가 실행 후 **ACK** 회신
4. ACK를 받아야만 앱에 "실행 완료" 표시 (10초 내 없으면 "시간 초과")

## 6. 안전 설계
- 명령마다 고유 ID → **중복 실행 방지**, 유효시간 지난 명령은 장치가 거부
- 긴급 정지는 **최우선 처리 + 래치**(해제 명령 전까지 모든 동작 차단)
- 서보는 **한 번에 1개만** 구동 (전원 피크 제한), 회전 각도 상·하한 제한
- 네트워크 끊김 시 안전 위치로 복귀, 새 동작 금지
- 전기: Echo 5V → 분압 저항으로 3.3V, 서보는 별도 5V 전원 + 공통 GND

## 7. 실시간 동기화와 장애 대응
- 웹·앱 공용 TypeScript 모듈(`shared/`)로 동일한 데이터 모델·재연결 로직 사용
- WebSocket 끊김 → 지수 백오프 재연결 → REST로 최신 상태 재동기화
- 장치 비정상 종료 → MQTT **Last Will**로 즉시 "연결 끊김" 표시

## 8. 하드웨어 없이 개발: 시뮬레이터
- Python Mock 장치가 실제 ESP32와 같은 MQTT 규격으로 동작
- 시나리오: 정상 / 적재율 증가 / 센서 고장 / 이상값 / 연결 끊김 / ACK 미응답
- 모든 시뮬레이터 데이터에 `simulator` 표시 → 화면에 SIMULATED 배지
- 실제 장치 전환: Wi-Fi·서버 주소·핀·보정값만 설정

## 8-1. 하드웨어 추상화 (HAL)
- `HARDWARE_MODE=SIMULATOR | ESP32_REAL` 환경변수 하나로 전환
- 두 모드가 **같은 MQTT 규격·같은 서버 경로** → 실제 ESP32 연결 시 웹·앱 수정 없음
- 모드와 다른 출처의 데이터는 서버가 폐기 → 가상 데이터가 실제 데이터로 기록될 수 없음

## 9. 검증 결과 (시뮬레이터 기준)
- 자동 테스트: 백엔드 79 · 웹 67 · 앱 54 통과, 펌웨어 빌드 성공
- 통합 시나리오 26개 통과 (센서·제어·AI 자동 분류·장애 복구)
- 독립 코드 리뷰 10건 발견 → 전부 조치 (docs/CODE_REVIEW.md)
- 시뮬레이터 통합 검증 17개 항목 통과 (MQTT→DB→WS, ACK, 타임아웃, LWT)
- ⚠️ 실제 하드웨어 검증은 미실시 — 배선·전원·보정은 조립 후 진행

## 10. 남은 단계
- 하드웨어 조립 → 핀맵 확정 → 실기 시험 15항목 (절차 문서화 완료)
