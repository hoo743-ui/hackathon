# SMART RECYCLE — 발표 자료 원고 (PPT 생성용)

> **PPT 생성 AI에게 주는 지시**
> - 아래 `## 슬라이드 N` 하나를 슬라이드 한 장으로 만든다. 총 14장 + 부록 1장.
> - 각 슬라이드의 **제목 / 핵심 문장 / 본문 / 시각 자료 / 발표 멘트**를 사용한다. 발표 멘트는 슬라이드 노트에 넣는다.
> - 톤: 해커톤 발표, 한국어, 간결. 한 장에 글머리 5개 이하.
> - 디자인: 재활용 느낌의 차분한 색(진녹·청회색·흰 배경), 재질 색 4개(플라스틱 청색 · 금속 보라 · 종이 황토 · 유리 회색)를 일관되게 사용.
> - 표와 흐름도는 도형으로 다시 그린다. 숫자는 이 원고에 있는 것만 쓰고 새로 만들지 않는다.

## 슬라이드 1 — 표지
- **제목**: SMART RECYCLE
- **부제**: AI 카메라가 분류하고, 기계가 넣고, 관리자는 실시간으로 본다
- **하단**: 해커톤 2026 · 팀명 / 팀원 이름 (직접 입력)
- **시각 자료**: 골판지 분리수거 프로토타입 사진 (팀 사진 사용)
- **발표 멘트**: "쓰레기를 넣기만 하면 AI가 종류를 알아보고 알맞은 칸으로 옮기는 스마트 분리수거함, SMART RECYCLE입니다."

## 슬라이드 2 — 문제
- **핵심 문장**: 분리배출은 '귀찮고 헷갈려서' 실패한다
- **본문**
  - 재질이 헷갈리는 쓰레기(코팅 종이, 캔·유리병)는 잘못 버려지기 쉽다
  - 잘못 섞이면 선별장에서 다시 손으로 골라야 한다
  - 공공장소 수거함은 언제 가득 찼는지 관리자가 알기 어렵다
- **시각 자료**: 섞여 버려진 쓰레기통 아이콘 → 물음표
- **발표 멘트**: "사람에게 분류를 맡기지 말고, 수거함이 직접 분류하고 상태를 알려 주면 어떨까 생각했습니다."

## 슬라이드 3 — 해결책 한눈에
- **핵심 문장**: 인식 → 분류 → 기록 → 실시간 공유를 하나의 흐름으로
- **본문 (4단계 가로 흐름)**
  1. **인식**: 카메라 + YOLO 모델이 쓰레기 종류 판별 (유리·금속·종이·플라스틱)
  2. **분류**: Arduino가 서보모터 3개로 해당 칸에 투입
  3. **측정**: 초음파 센서로 적재 높이 측정 → 적재율 계산
  4. **공유**: 서버에 사진·결과 저장 → 관리자 웹·모바일 앱에 실시간 표시
- **시각 자료**: 4개 아이콘(눈 · 톱니 · 자 · 스마트폰)을 화살표로 연결
- **발표 멘트**: "투입부터 관리자 화면까지 사람 손을 거치지 않고 이어집니다."

## 슬라이드 4 — 시스템 구성
- **핵심 문장**: 역할을 셋으로 나눠 하나가 멈춰도 나머지는 동작
- **본문 (3개 박스)**
  | 구성 | 장비 | 역할 |
  |---|---|---|
  | 카메라 컴퓨터 | Windows 노트북 + 카메라 | YOLO 추론, 하드웨어 명령, 서버 전송 (단일 실행 프로그램 SMART_RECYCLE_AI) |
  | 하드웨어 | Arduino UNO R3 · ESP32 DevKitC V4 · SG90 ×3 · HC-SR04 ×1 | 서보 분류 동작, 거리 측정, 동작 완료 응답 |
  | 중앙 서버 | MacBook | FastAPI 서버 · PostgreSQL · 이미지 저장 · WebSocket |
  | 관리자 | 웹 브라우저 · 스마트폰 앱 | 실시간 인식 결과 · 적재율 · 장치 상태 |
- **시각 자료**: 아래 구조도를 도형으로
  ```
  [카메라] → [카메라 컴퓨터: YOLO] ─USB→ [Arduino UNO: 서보 3 · 초음파 1] ─UART→ [ESP32]
                     │ HTTP (이미지+결과)
                     ▼
              [MacBook 서버: FastAPI · DB · 이미지] ─WebSocket→ [관리자 웹] [모바일 앱]
  ```
- **발표 멘트**: "AI와 하드웨어 제어는 현장 컴퓨터에서, 저장과 실시간 공유는 중앙 서버에서 담당합니다. 서버가 잠시 끊겨도 분류 동작은 계속됩니다."

## 슬라이드 5 — AI 인식
- **핵심 문장**: 학습된 YOLO 모델로 실시간 '추론만' 수행
- **본문**
  - 모델 `best_model.pt` 클래스: Glass · Metal · Paper · Plastic · Waste (분류 대상은 앞의 4개)
  - 실행 시 모델 1회 로드, 학습 없이 추론만 (GPU 있으면 GPU, 없으면 CPU 자동 선택)
  - 신뢰도 기준 0.65 — 빈 배경을 플라스틱으로 잡던 오인식을 막기 위해 0.5에서 상향
  - **투입 1회 = 분류 1회**: 같은 종류가 4프레임·0.4초 연속 보여야 확정, 물체가 사라지기 전까지 다시 세지 않음
- **시각 자료**: 바운딩 박스가 그려진 인식 화면 캡처 (시연 중 캡처한 실제 사진 사용)
- **발표 멘트**: "카메라 앞에서 물체가 흔들려도 한 번만 처리되도록, 연속으로 같은 결과가 나올 때만 확정합니다."

## 슬라이드 6 — 하드웨어 분류 장치
- **핵심 문장**: 서보 3개로 4종류를 나눈다
- **본문**
  - 서보 X(D9): 분류 방향 회전 — 플라스틱 30° · 금속 145° · 유리 160° · 종이 180°
  - 서보 Y1(D10)·Y2(D11): 뚜껑을 기울여 투하 → 원위치
  - 동작 순서: 회전 → 4초 → 투하 → 2초 → 복귀 (약 6초)
  - 초음파 HC-SR04(D4/D5) 1개: 1초마다 거리 측정
  - ESP32: Arduino 데이터를 받아 중계 (Wi-Fi 전송 확장 가능)
- **시각 자료**: 프로토타입 사진 + 서보 위치 표시, 각도 반원 다이어그램
- **발표 멘트**: "서보 하나가 방향을 정하고, 나머지 두 개가 뚜껑을 기울여 떨어뜨립니다. 그래서 세 개로 네 종류를 나눌 수 있습니다."

## 슬라이드 7 — 동작 성공을 '확인'하는 프로토콜
- **핵심 문장**: 명령을 보냈다고 성공이 아니다 — 장치가 '완료'라고 답해야 성공
- **본문**
  | 카메라 컴퓨터 → Arduino | Arduino → 카메라 컴퓨터 | 화면 표시 |
  |---|---|---|
  | `L` (플라스틱) | `ACK:L:START` → `ACK:L:DONE` | **분류 성공** |
  | 동작 중 새 명령 | `ACK:G:BUSY` | 실패 (장치 동작 중) |
  | 응답 없음 10초 | — | 실패 (응답 시간 초과) |
  | `S` (비상 정지) | `ACK:S:DONE` | 중단 |
  - 거리: `DIST:18.0` 매 1초, 측정 실패 `DIST:ERR`
- **시각 자료**: 시퀀스 다이어그램 (카메라 컴퓨터 ↔ UNO)
- **발표 멘트**: "기존 코드는 명령만 보내고 결과를 몰랐습니다. 저희는 펌웨어가 완료 응답을 보내게 해서, 실제로 동작을 끝냈을 때만 '성공'으로 표시합니다."

## 슬라이드 8 — 적재율 측정
- **핵심 문장**: 센서 1개, 거짓 없는 적재율
- **본문**
  - 적재율(%) = (1 − 측정 거리 ÷ 빈 통 거리) × 100
  - 최근 5개 값의 중앙값으로 튀는 값 제거
  - 5초간 값이 없으면 `SENSOR_DISCONNECTED` 표시 — 값을 지어내지 않음
  - 센서가 없는 칸은 '수신 없음'으로 정직하게 표시
- **시각 자료**: 쓰레기통 단면도(센서 → 쓰레기 높이 화살표) + 수식
- **발표 멘트**: "예를 들어 빈 통이 30cm이고 18cm가 측정되면 적재율 40%입니다. 센서가 끊기면 숫자 대신 '연결 끊김'을 보여 줍니다."

## 슬라이드 9 — 중앙 서버
- **핵심 문장**: 사진과 결과를 같은 ID로 묶어 저장하고 즉시 알린다
- **본문**
  - FastAPI + PostgreSQL, 이미지 파일 저장(JPEG/PNG 검사)
  - 인식 1건 = Detection ID 1개 → 사진·종류·신뢰도·바운딩 박스·하드웨어 결과가 한 기록
  - 저장이 끝난 뒤에만 WebSocket으로 웹·앱에 동시 발행
  - 같은 ID 재전송은 중복 저장하지 않음
- **시각 자료**: 기록 카드 예시 (사진 썸네일 + 필드 목록)
- **발표 멘트**: "웹과 앱은 같은 이벤트를 받기 때문에 서로 다른 데이터를 보여 줄 수 없습니다."

## 슬라이드 10 — 관리자 웹 · 모바일 앱
- **핵심 문장**: 투입하는 순간 관리자 화면이 바뀐다
- **본문**
  - 실시간 인식: 최신 사진 · 종류 · 신뢰도 · 촬영 시각 · Detection ID · 하드웨어 결과
  - 카메라 컴퓨터 상태: 카메라 · 모델 · Arduino · 서보 ×3 · 초음파 · ESP32 · 전송 대기
  - 수거함: 칸별 적재율, 분류 기록: 사진 썸네일 이력
  - 모바일 앱(React Native/Expo)도 같은 서버·같은 이벤트
- **시각 자료**: 웹 개요 화면 캡처 + 폰 홈 화면 캡처를 나란히 (시연 중 캡처)
- **발표 멘트**: "왼쪽은 관리자 웹, 오른쪽은 휴대폰 앱입니다. 같은 Detection ID가 동시에 나타납니다."

## 슬라이드 11 — 현장에서 멈추지 않게 (안정성)
- **핵심 문장**: 네트워크·장치가 흔들려도 시연은 계속된다
- **본문**
  - **서버가 끊겨도**: 분류·모터는 계속, 못 보낸 결과는 저장했다가 복구 시 자동 재전송 (중복 없음)
  - **맥북 IP가 바뀌어도**: 서버가 2초마다 위치 신호를 방송 → 카메라 컴퓨터가 새 주소로 자동 전환 (실측 4초)
  - **장치가 끊겨도**: 명령을 보내지 않고 화면에 원인 표시, 자동 재연결
  - **비상 정지**: 카메라 컴퓨터 프로그램의 버튼 → 서보 즉시 대기 자세
  - 시리얼 포트는 프로그램 하나만 사용 (동시 접근 충돌 방지)
- **시각 자료**: 끊김 → 대기열 → 복구 → 재전송 순환 화살표
- **발표 멘트**: "행사장 와이파이처럼 불안정한 환경을 가정하고 만들었습니다."

## 슬라이드 12 — 개발 중 해결한 문제
- **핵심 문장**: 코드를 직접 분석해 숨은 오류를 찾았다
- **본문**
  | 문제 | 원인 | 해결 |
  |---|---|---|
  | 한 번 넣었는데 모터가 두 번 동작 | 카운트 메시지 `C:L:3`의 `L`을 Arduino가 명령으로 오인 | 한 글자 명령만 전송, 펌웨어도 한 글자 줄만 인정 |
  | ESP32로 센서 정보가 안 감 | Arduino는 `FULL:`, ESP32는 `DATA:`만 처리 | 통합 프로토콜(`HELLO/ACK/DIST`)로 정리 |
  | 성공 여부를 알 수 없음 | 펌웨어 응답 없음 | ACK 응답 추가 |
  | 빈 배경을 플라스틱으로 인식 | 신뢰도 기준 0.5 | 0.65로 상향, 카메라를 투입구로 고정 |
  | 행사장 Wi-Fi에서 연결 불가 | 기기 간 통신 차단 | 핫스팟 + IP 자동 추적 |
- **발표 멘트**: "실제 장비로 테스트하면서 발견한 문제들을 하나씩 해결했습니다."

## 슬라이드 13 — 라이브 시연
- **핵심 문장**: 지금 쓰레기를 넣어 보겠습니다
- **본문 (시연 순서)**
  1. 플라스틱병 투입 → 카메라 화면에 'Plastic' 표시
  2. 서보가 플라스틱 칸으로 회전·투하 → '분류 성공'
  3. 웹·휴대폰에 같은 사진·같은 Detection ID 표시
  4. 금속 캔 / 종이 / 유리병 순서로 반복
  5. 센서 앞을 가려 적재율 변화 확인
- **시각 자료**: 큰 글씨 "LIVE DEMO" + 순서 체크리스트
- **발표 멘트**: (시연 진행) "카메라 컴퓨터 화면, 관리자 웹, 휴대폰을 함께 봐 주세요."

## 슬라이드 14 — 기대 효과와 확장
- **핵심 문장**: 공공장소 분리수거를 자동화하고 데이터로 관리
- **본문**
  - 이용자: 고민 없이 투입 → 올바른 분리배출
  - 관리자: 적재율·이상 알림으로 수거 시점 판단, 원격 모니터링
  - 확장: 칸마다 초음파 센서 추가, 일반쓰레기(Waste) 칸 추가, 여러 대 수거함 통합 관리, 수거 경로 최적화
- **시각 자료**: 공원·학교·지하철역 아이콘에 수거함 여러 대 → 중앙 대시보드
- **발표 멘트**: "한 대의 프로토타입이지만, 같은 구조로 여러 대를 한 서버에서 관리할 수 있습니다. 감사합니다."
