# 서비스 구조 재설계 v2 — Public Smart Waste Management (단일 장치 MVP)

> 디자인 시스템(Material Ledger 토큰·타이포·재질 코드·Material Column)은 `REDESIGN_PLAN.md` 그대로 유지한다. 바뀌는 것은 **메뉴·화면 구성과 우선순위**다.
> 정보 우선순위: ① 장치 정상 여부 ② 칸별 적재량 ③ AI 분류 과정·결과 ④ 오류·점검 알림 ⑤ 운영 기록

## 1. 역할
| 주체 | 역할 |
|---|---|
| 스마트 쓰레기통 (ESP32 / 시뮬레이터) | 적재 측정, 배출구 서보 |
| AI 분류 프로그램 (다른 노트북, 기존 코드) | 촬영·분류 → `POST /api/detections` (`docs/AI_INTEGRATION.md`) |
| 관리자 웹 | 운영 현황·기록 |
| 관리자 앱 | 현장 확인·제어·알림 |

## 2. 기존 기능 분류 (A 재사용 / B 수정 / C 제거·통합)
| 기능 | 분류 | 처리 |
|---|---|---|
| REST·WS·MQTT·DB·HAL·명령 안전·시뮬레이터 | A | 그대로 |
| 웹 개요·수거함·장치 페이지, Material Column 등 컴포넌트 | A/B | 재배치 |
| 웹 제어 센터 | B | **운영(Operations)** 으로 확장 (모터·센서 테스트, 점검 기록) |
| 웹 이력 | B | 측정 이력 → 수거함 상세, 명령 이력 → 운영, **분류 기록**은 신규 페이지 |
| 웹 분석 | C | 독립 페이지 삭제. 적재 추이 → 수거함, 재질별 건수 → 분류 기록 요약, 센서 가용률 → 장치 |
| 웹 설정 | C | 독립 페이지 삭제. 보정·임계값 → 수거함 상세, 연결·HW 모드 → 장치, 테마·토큰·데이터 출처 → 헤더 메뉴 |
| 앱 이력·설정 탭 | C | 탭 삭제. 설정 → 홈 헤더 아이콘(스택 화면), 명령 기록 → 제어 화면 하단, 분류 기록 → 홈 |
| AI 분류 | 신규 | `detection_logs` 확장, 자동 모드 시 `origin=auto` 배출 명령 |
| 알림 | 신규 | `shared/src/alerts.ts` `deriveAlerts()` — 저장하지 않고 현재 상태에서 파생 |
| 점검 기록 | 신규 | `maintenance_logs`, `POST/GET /api/maintenance` |

## 3. 웹 메뉴 (5개)
| 메뉴 | 경로 | 내용 |
|---|---|---|
| 개요 | `/` | 장치 상태 · **오늘 분류 건수**(`detectionSummary(오늘 0시)`) · 점검 필요(`needsAttention`, 알림 상위 목록) · 4칸 Material Column · 최근 분류(분류→처리 결과) · 최근 오류/이벤트 |
| 수거함 | `/bins`, `/bins/:binId` | 4칸 적재율·거리·센서·임계 경고 / 상세: 측정 이력 차트·표, 24h 추이, 보정(편집), 임계값(읽기) |
| 분류 기록 | `/sorting` | AI 분류 표: 시각 · 종류(코드칩) · confidence(모델값 그대로, 소수 2자리, 임계값 표시) · 처리 결과(`DETECTION_OUTCOME_LABELS`) · 연결 명령/ACK · 출처(model/simulator) · 모델명. 필터(종류·결과·출처·기간)·페이지. 상단 요약: 오늘/기간 건수, 재질별 건수, 결과별 건수 |
| 장치 | `/devices` | 장치 ID · 연결 · 마지막 통신 · 서버↔브로커(MQTT) · HW 모드 · 센서 상태(칸별) · 장치 오류(error_code) · 펌웨어 · 모터(마지막 배출 결과) · 마지막 AI 분류 수신 시각 |
| 운영 | `/operations` | 긴급정지 · 운전 모드(자동=AI 분류 동작 / 수동=관리자 조작) · 수동 제어(배출구) · **모터 테스트**(칸별 배출 → ACK → 결과를 점검 기록으로 저장 버튼) · **센서 테스트**(칸별 실시간 거리·상태·측정 시각 신선도 → 정상/이상 기록) · 상태 확인(GET_STATUS) · 점검 기록 작성·목록 · 최근 제어 기록 |

리다이렉트: `/control`→`/operations`, `/history`→`/sorting`, `/analytics`→`/bins`, `/settings`→`/devices`.

## 4. 앱 탭 (4개)
| 탭 | 내용 |
|---|---|
| 홈 | 장치 상태 한 줄 · 오늘 분류 건수 · 4칸 컴팩트 컬럼 · 최근 이벤트(분류 결과 + 알림 상위 3) · 헤더 ⚙ → 설정(스택) |
| 수거함 | 칸 목록 → 상세(적재율·거리·센서·이력) |
| 알림 | `deriveAlerts()` 전체, 심각도 순, 탭 배지 = critical+warning 수, 항목 탭 → 관련 화면 |
| 제어 | 운전 모드 · 배출구(길게 누르기) = 수동 제어/모터 테스트 · 상태 확인 · 결과·오류 · 최근 제어 기록 · 긴급정지 바(고정) |

## 5. 정확성 규칙
- confidence는 모델 출력 그대로 표시. 시뮬레이터 분류(`source=simulator`)는 "시뮬레이터" 표시
- 분류 기록(`detections`)과 제어 기록(`commands`)은 다른 표·다른 화면. 자동 명령(`origin=auto`)은 제어 기록에서 "AI 자동"으로 구분
- AI 프로그램은 상태 신호가 없다 → "AI 연결됨"을 표시하지 않는다. "마지막 분류 수신 n분 전"만 표시
- 센서 오류(sensor_status) ≠ 장치 오프라인(connection_status) — 다른 알림 종류
- 분류 건수·통계는 실제 `detection_logs`만. 데이터가 없으면 "아직 분류 기록 없음"
- 배출 성공은 ACK(SUCCEEDED/SORTED) 이후에만
