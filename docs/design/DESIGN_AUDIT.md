# 디자인 감사 (재디자인 전)

근거: 실제 렌더링 스크린샷 (`scripts/screenshot.sh`, 1440px·390px), 소스 코드.

## 시각적 문제
| # | 문제 | 근거 |
|---|---|---|
| V1 | 모든 정보가 같은 모양의 둥근 카드 → 위계 없음, 템플릿 느낌 | 대시보드 KPI 4개·bin 4개·차트·명령이 모두 동일 카드 |
| V2 | 범용 SaaS KPI 행 (평균/주의/장치/업데이트)이 같은 크기·무게 | 운영상 중요도(위험 bin > 평균)가 반영되지 않음 |
| V3 | 인디고 primary + 다크 네이비 = 흔한 AI 대시보드 팔레트 | `tokens.css` |
| V4 | 알약(pill) 배지 남용, 같은 단어 중복 ("여유"+"정상", "위험" 배지 + 빨간 숫자 + 빨간 막대 + 경고 박스로 4중 강조) | bin 카드 |
| V5 | 적재율이 가로 진행 막대 → 임계값(50/80/95) 위치를 보여주지 않아 분석 가치 없음 | `BinCard`, 앱 `FillBar` |
| V6 | 쓰레기 종류(플라스틱/캔/종이/일반)를 구분하는 시각 정체성 없음 — 아이콘만 다름 | 4개 카드가 시각적으로 동일 |
| V7 | 실시간 차트가 세션 중 수신 점만 표시 → 진입 직후 비어 있음, 이력 데이터 미활용 | `FillChart` |
| V8 | 390px에서 내비게이션이 가로 스크롤 속에 숨음, KPI가 세로로 길게 나열되어 핵심(4개 bin)이 화면 밖 | 390px 스크린샷 |
| V9 | 타이포그래피 정체성 없음 (Pretendard 단일, 숫자 표현 위계 약함), 대문자 `SIMULATED / MOCK` | |
| V10 | 테마 전환 없음 (OS 설정만) | |

## 정보 구조 문제
| # | 문제 |
|---|---|
| I1 | 웹 페이지 3개뿐 (대시보드/상세/장치) — 요구 7개(개요·수거함·장치·제어·이력·분석·설정) 중 제어·이력·분석·설정 없음 |
| I2 | 장치 상태가 "연결됨/끊김" 2단계 — 저하(센서 이상·긴급정지·모터 실패) 구분 없음 |
| I3 | 앱 탭 3개 — 수거함·이력 진입 경로 부족 |
| I4 | 보정 설정이 bin 상세 하단에 묻혀 있음, 데이터 소스(Mock) 전환이 사이드바 하단에 상시 노출 |

## 기능적 위험 (재디자인 중 지켜야 할 것)
| # | 위험 | 대응 |
|---|---|---|
| F1 | 명령 ACK 전 성공 표시 | `CommandStatus` 컴포넌트가 SUCCEEDED에서만 "실행 완료" — 테스트로 고정 |
| F2 | 미보정(null)을 0%로 표시 | 공용 포맷 함수만 사용 — 테스트로 고정 |
| F3 | 앱 제어가 `devices[0]` 고정 | 장치 1대 전제 명시, 장치 ID를 화면에 표시 |
| F4 | Mock 데이터가 실제처럼 보임 | 시뮬레이터/Mock 표시는 재디자인 후에도 유지 (형태만 변경) |
| F5 | 웹에 제어 기능 신규 추가 → 실수 조작 위험 | 2단계 확인(배출구), 긴급정지는 즉시(안전 방향), 해제는 확인 |
| F6 | 폰트 교체 시 한글 깨짐/오프라인 로딩 실패 | 로컬 번들 폰트만 사용 (CDN 금지) |
